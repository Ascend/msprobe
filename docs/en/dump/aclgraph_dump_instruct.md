# aclgraph_dump Instructions

## Overview

**aclgraph_dump** provides the following data collection capabilities for PyTorch ACLGraph scenarios:

- Single-point collection through `acl_save`.
- Whole-network statistics or tensor collection through `AclGraphDumper`, including custom API collection and dynamic collection control.

## Preparations

**Environment Setup**

1. Install and correctly configure Ascend Extension for PyTorch (torch_npu) and CANN.
2. Install msProbe by referring to [msProbe Installation Guide](../msprobe_install_guide.md).
3. When installing from source code, include the `aclgraph_dump` module during compilation and installation.

   ```bash
   python3 build.py -e include-mod=aclgraph_dump -e no-check=true
   ```

**Constraints**

- Only the PyTorch framework is supported.
- torch_npu is required for compiling `aclgraph_dump`. If this module is not included, `msprobe.lib.aclgraph_dump_ext` cannot be imported.

## Whole-Network Collection

### Quick Start

Configure the collection task in `config.json` before capturing the graph. The following example collects whole-network statistics:

```json
{
    "task": "statistics",
    "dump_path": "./L0_dump",
    "rank": [],
    "level": "L0",
    "statistics": {
        "list": ["linear", "attention"],
        "slice": [{"end": 1024}]
    }
}
```

Create and start `AclGraphDumper` before graph capture, and call `step()` after each replay to flush or archive the collected data:

```python
from msprobe.pytorch import AclGraphDumper

dumper = AclGraphDumper("./config.json")
dumper.start(model)

graph = torch.npu.NPUGraph()
with torch.npu.graph(graph):
    static_output = model(static_input)

for data in real_inputs:
    static_input.copy_(data)
    graph.replay()
    dumper.step()
```

`AclGraphDumper` supports the following configuration items:

| Item | Mandatory | Description |
| --- | --- | --- |
| `task` | No | Collection task. The options are `statistics` and `tensor`. The default value is `statistics`. |
| `dump_path` | Yes | Output directory. The tool checks and creates the directory. |
| `rank` | No | Ranks to collect, in `list[int \| str]` format. An empty list collects all ranks. A string must use the `"start-end"` range format. |
| `dump_enable` | No | Collection switch of the Boolean type. The default value is `true`. It can be changed at runtime. For details, see [Dynamic Start and Stop](#dynamic-start-and-stop). |
| `level` | No | Collection level. The options are `L0`, `L1`, and `mix`. `L0` collects module inputs and outputs, `L1` collects API inputs and outputs, and `mix` collects both. |
| `list` | No | Keywords used to filter module or API names, in `list[str]` format. An empty list collects all data covered by `level`. |
| `custom_api` | No | Fully qualified import paths of custom Python APIs, in `list[str]` format. This item is supported only when `task` is set to `tensor`. |
| `slice` | No | Tensor slice configuration in `list[dict]` format. This item takes effect only when `task` is set to `statistics`. |

### API Description

```python
AclGraphDumper(config_path: str | None = None)
AclGraphDumper.start(model: torch.nn.Module) -> None
AclGraphDumper.step(dump: bool = True) -> None
```

- `config_path` specifies the configuration file. If it is not specified, the built-in `config.json` is used.
- `start()` installs the collection logic and must be called before graph capture.
- For a `statistics` task, `step(dump=True)` writes `dump.json` and advances the step ID. `step(dump=False)` clears the current statistics without writing a file or advancing the step ID.
- For a `tensor` task, `step()` archives the `.pt` files generated by the current replay and advances the step ID. The `dump` argument applies only to a `statistics` task.

### Whole-Network Tensor Collection

Set `task` to `tensor` to save the actual input, keyword argument, and output tensors of modules or APIs in the collection scope:

```json
{
    "task": "tensor",
    "dump_path": "./tensor_dump",
    "rank": [],
    "dump_enable": true,
    "level": "mix",
    "tensor": {
        "list": ["linear", "attention"]
    }
}
```

Call `dumper.step()` after each graph replay. The tensors generated by the same API call share a replay-time call index. File names use the following format:

```text
{api_name}.{call_index}.{input|input_kwargs|output}[.{index}].pt
```

Whole-network tensor collection can generate substantial disk and data transfer overhead. Use `level` and `list` to narrow the collection scope.

### Custom API Collection

For a Python API that cannot be discovered through module hooks or PyTorch dispatch, specify its fully qualified import path in `tensor.custom_api`. This capability is supported only for a `tensor` task.

```json
{
    "task": "tensor",
    "dump_path": "./tensor_dump",
    "level": "L1",
    "tensor": {
        "custom_api": [
            "my_package.ops.reshape_and_cache"
        ]
    }
}
```

`AclGraphDumper.start()` resolves and wraps each target before graph capture. Tensor objects nested in positional arguments, keyword arguments, and return values are collected. Note the following restrictions:

- Each value must be the fully qualified path of an importable callable.
- The model must invoke the object associated with that path. A function reference copied to another variable before `start()` is not wrapped.
- `custom_api` takes effect during `start()`. Changing it at runtime does not wrap additional APIs.
- The inputs, keyword arguments, and outputs of one custom API call share the same replay-time call index.

### Dynamic Start and Stop

Set the root-level `dump_enable` field to control both `statistics` and `tensor` collection:

```json
{
    "task": "tensor",
    "dump_path": "./tensor_dump",
    "dump_enable": false,
    "level": "L1",
    "tensor": {
        "list": []
    }
}
```

Call `AclGraphDumper.start()` before graph capture even if the initial value is `false`, because the collection nodes must be captured in the ACLGraph. At runtime, update `dump_enable` in the same configuration file without recapturing the graph:

- `dumper.step()` detects configuration file changes and refreshes the switch.
- The updated value takes effect for subsequent graph replays.
- Only `dump_enable` is refreshed dynamically. Runtime changes to `task`, `level`, `list`, `custom_api`, or `slice` do not change the captured graph.

To apply a changed value before the next replay, update the configuration file and call `dumper.step()` to refresh the switch. For a `statistics` task, use `dumper.step(dump=False)` to avoid generating `dump.json` for the current step. For a `tensor` task, `dumper.step()` also archives pending `.pt` files and advances the step ID.

### Output

For a `statistics` task, the output paths are:

- Single-card: `dump_path/step{step_id}/pid{pid}/dump.json`
- Multi-card: `dump_path/step{step_id}/rank{rank_id}/dump.json`

The generated `dump.json` files can be compared using `msprobe compare`.

For a `tensor` task, the output paths are:

- Single-card: `dump_path/step{step_id}/pid{pid}/tensor_data/*.pt`
- Multi-card: `dump_path/step{step_id}/rank{rank_id}/tensor_data/*.pt`

The `.pt` files can be loaded using `torch.load`.

A `tensor` task does not generate `dump.json`.

## Single-Point Collection

### Quick Start

The following example shows how to save a tensor in the forward process:

```python
import torch
import torch_npu

from msprobe.pytorch import acl_save

class ToyModel(torch.nn.Module):
    def __init__(self):
        super().__init__()
        self.linear = torch.nn.Linear(8, 4)

    def forward(self, x):
        y = self.linear(x)
        # Save the intermediate tensor.
        acl_save(y, "./dump/linear_out.pt")
        return y

if __name__ == "__main__":
    model = ToyModel().to("npu:0")
    x = torch.randn(2, 8, device="npu:0")
    out = model(x)
```

### Function Description

#### Function Overview

`acl_save` is used to save tensor data. After this API is called, a `.pt` file is saved.

#### API Description

**Prototype**

```python
acl_save(x: torch.Tensor, path: str) -> torch.Tensor
```

**Parameters**

| **Parameter**| **Type**| **Description**| **Mandatory (Yes/No)**|
| --- | --- | --- | --- |
| x | torch.Tensor | Tensor to be saved.| Yes|
| path | String| Saving path (relative or absolute path), which is of the string type. The name of the actual flushed file is in the format of `{base}_{seq}.pt`. For example, if `./dump/act.pt` is passed, `./dump/act_0.pt` and `./dump/act_1.pt` are actually flushed. (The parent directory `./dump/` must be an existing directory.)| Yes|

**Returns**

Returns a tensor with the same shape as the input, which has no specific meaning and is used only to trigger the saving operation.

#### Examples

##### 1. Single-point saving during inference

```python
from msprobe.pytorch import acl_save

logits = model(x)
acl_save(logits, "./dump/logits.pt")
```

##### 2. Single-point collection in a multi-card scenario

Use a rank-specific directory to prevent different processes from writing to the same path. Ensure that the directory exists before calling `acl_save`.

```python
acl_save(tensor, f"./dump/rank{torch.distributed.get_rank()}/tensor.pt")
```

##### 3. Saving the file called for multiple times

```python
for step in range(3):
    y = model(x)
    acl_save(y, "./dump/act.pt")
```

`./dump/act_0.pt`, `./dump/act_1.pt`, and `./dump/act_2.pt` are generated.

### Output Description

#### Dump Result File

After `acl_save` is called, `.pt` files are generated in the directory specified by `path`.

#### Data Parsing

Data is saved in the PyTorch `.pt` format (pickle serialization) and can be read using `torch.load`.

```python
import torch

tensor = torch.load("./dump/act_0.pt")
```

## Appendix

### FAQs

**1. Failed to import msprobe.lib.aclgraph_dump_ext**

Check the following items:

- msProbe is compiled and installed using `python3 build.py -e include-mod=aclgraph_dump -e no-check=true`.
- torch_npu is installed and its environment variables are correctly configured.
- The current operating system is Linux.

**2. `Allocate SQ failed`**

In CANN versions earlier than 8.5.0, `Allocate SQ failed` may occur because SQ is not reused. Change `CurrentNPUStream` to `DefaultNPUStream` in `ccsrc/aclgraph_dump/aclgraph_dump.cpp` as a workaround, or upgrade to CANN 8.5.0 or later.
