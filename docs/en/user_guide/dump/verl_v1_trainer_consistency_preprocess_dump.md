# Collecting Data for verl V1 Trainer Training-Inference Consistency Comparison

## Introduction

This document uses verl v0.9.0.dev as an example to introduce the adaptation method for collecting training-inference consistency comparison data under the V1 Trainer and the current Fully Async architecture, applicable to the FSDP or Megatron training backend.

The main entry point of verl v0.8.0 adopts Hybrid AgentLoop, and the data generated by rollout is organized by the trainer and enters the training process. verl v0.9.0.dev introduces the V1 Trainer, which passes the data generated by AgentLoop to the training side through TransferQueue and organizes the training batch using a jagged TensorDict. The change in the data path enables V1 to support synchronous training through the same trainer entry, as well as asynchronous training under different resource deployment schemes. Training-inference consistency collection also needs to correspondingly adjust the transfer position of the request ID and the trimming method of the prompt-only input.

The V1 Trainer is enabled by `trainer.use_v1=True`, and the following three modes are selected through `trainer.v1.trainer_mode`:

| Mode | Configuration Value | Description |
| --- | --- | --- |
| Sync | `sync` | rollout and training are executed sequentially by step; the trainer waits for the rollout data of the current step before training, and the data is passed through TransferQueue |
| Colocate Async | `colocate_async` | rollout and training are scheduled asynchronously but deployed on the same set of computing resources, suitable for resource sharing scenarios |
| Separate Async | `separate_async` | rollout and training are scheduled asynchronously and deployed on mutually independent computing resources, decoupling the execution of both sides through a queue |

verl also provides an independent Fully Async implementation in `verl.experimental.fully_async_policy`.
This implementation does not belong to the above three V1 Trainer modes, and still connects the Rollouter and Trainer through MessageQueue.
Its core collection scheme is consistent with verl v0.8.0, but the request ID processing position and the partial rollout processing method have changed.

This document uses "[Collecting Data for Asynchronous verl Training-Inference Consistency Comparison](./verl_async_consistency_preprocess_dump.md)" as the baseline, and only introduces the changes newly added or different in verl v0.9.0.dev. Common changes not expanded in this document follow the baseline document.

## Preparations

First, according to the actual training backend, complete the [preparations](./verl_async_consistency_preprocess_dump.md#preparations) and [msProbe configuration](./verl_async_consistency_preprocess_dump.md#msprobe-configuration-files) in the baseline document.

### V1

The following code block summarizes the parameters that need to be modified in the baseline document and V1, and can be directly merged into the `main_ppo` startup script. `/home/config_generate.json` is an example path, and it needs to be replaced with the actual path of the inference-side msProbe configuration file when used.

```diff
export DUMP_ON=1                # Enable training-side msProbe collection
export DUMP_PHASE=update_actor  # V1 prompt-only collection only supports the update_actor stage
export PROMPTS_ONLY=1           # Trim the training input to prompt-only

# The entry point is main_ppo
python3 -m verl.trainer.main_ppo \
    trainer.use_v1=True \
    trainer.v1.trainer_mode=sync \
    actor_rollout_ref.model.use_remove_padding=True \
    actor_rollout_ref.actor.use_dynamic_bsz=False \
    actor_rollout_ref.rollout.enforce_eager=True \
    '+actor_rollout_ref.rollout.engine_kwargs.vllm.additional_config={dump_config_path:"/home/config_generate.json"}' \
    trainer.val_before_train=False \
    trainer.balance_batch=False \
    ...
```

**Note**:

- The V1 prompt-only collection in this document only supports the `update_actor` stage, and `DUMP_PHASE=update_actor` must be set; the default `log_prob` of the baseline code cannot be directly used. This restriction does not apply to the standalone Fully Async scheme below.
- `PROMPTS_ONLY=1` changes the training input and is only used for training-inference consistency collection.
- The loss and gradients in this mode do not represent normal training results.
- After collection ends, `DUMP_ON`, `DUMP_PHASE`, `PROMPTS_ONLY`, and the inference-side
  `dump_config_path` should be unset to restore the normal training configuration.

### Fully Async

Fully Async continues to use the preparatory operations of the [baseline document](./verl_async_consistency_preprocess_dump.md#preparations), including independent Rollouter and Trainer resources, disabling `rollout_correction.bypass_mode`, and trimming the prompt-only input in `FullyAsyncTrainer`.

### V1 Component Changes

#### Passing request_id in AgentLoopWorkerTQ

**File involved in the current version**: `verl/trainer/ppo/v1/agent_loop_tq.py`

**Related file in the baseline document**: `verl/workers/rollout/llm_server.py`, used to inject `request_id`

**Description**: Add the request ID generated by rollout to the TransferQueue data, so that it is passed to the training side along with the training data, and used to associate the dump data on the inference side and the training side.

The request ID injected by `LLMServerClient` is located in `AgentLoopOutput.extra_fields`. V1 passes the rollout data to the training side through TransferQueue, and it is necessary to write this ID into the top-level `request_id` field when `AgentLoopWorkerTQ._agent_loop_postprocess()` assembles `field`:

```diff
class AgentLoopWorkerTQ(AgentLoopWorker):
    ...
    async def _agent_loop_postprocess(
        self,
        ...
    ) -> None:
        ...
        field = output.as_dict()
        field.update(kwargs)
+       extra_fields = field.get("extra_fields")
+       field["request_id"] = (
+           extra_fields.get("request_id")
+           if isinstance(extra_fields, dict)
+           else None
+       )
        ...
```

Even if the request ID is not obtained, the `request_id` field with the value `None` should be preserved, to avoid inconsistency in the data fields in the same
TransferQueue.

The request ID enters the training micro-batch through the following chain:

```text
LLMServerClient
  -> TokenOutput.extra_fields["request_id"]
  -> AgentLoopOutput.extra_fields
  -> AgentLoopWorkerTQ top-level field["request_id"]
  -> TransferQueue
  -> actor TensorDict
  -> FSDP or Megatron micro-batch
  -> update_actor_log.jsonl
```

#### Trimming Prompt-Only Input in the Actor Worker

**File involved in the current version**: `verl/workers/engine_workers.py`

**Corresponding file in the baseline document**: `verl/trainer/ppo/ray_trainer.py`, used for the
prompt-only trimming of Hybrid AgentLoop; V1 does not need to modify this file.

**Description**: Trim the training input to prompt-only, so that the training-side input is consistent with the inference-side prefill input.

In the baseline document, the Hybrid AgentLoop trims the padded DataProto by a fixed response length in `RayPPOTrainer.fit()`. The V1 input is a jagged TensorDict, and trimming needs to be performed in the actor worker according to the actual prompt length of each sample:

```diff
class ActorRolloutRefWorker(Worker, DistProfilerExtension):
    ...
    def update_actor(self, data: TensorDict) -> TensorDict:
+       if int(os.environ.get("PROMPTS_ONLY", "0")):
+           data = data.clone(recurse=False)
+           prompts = data["prompts"]
+           if prompts.is_nested:
+               prompt_lengths = prompts.offsets().diff().tolist()
+               data["input_ids"] = prompts
+               data["position_ids"] = torch.nested.as_nested_tensor(
+                   [
+                       position_ids[..., :prompt_length]
+                       for position_ids, prompt_length in zip(
+                           data["position_ids"].unbind(),
+                           prompt_lengths,
+                           strict=True,
+                       )
+                   ],
+                   layout=torch.jagged,
+               )
+               for key in (
+                   "responses",
+                   "rollout_log_probs",
+                   "response_mask",
+                   "loss_mask",
+                   "old_log_probs",
+                   "advantages",
+                   "rollout_is_weights",
+                   "ref_log_prob",
+               ):
+                   value = data.get(key)
+                   if isinstance(value, torch.Tensor):
+                       data[key] = (
+                           torch.nested.as_nested_tensor(
+                               [sample[:0] for sample in value.unbind()],
+                               layout=torch.jagged,
+                           )
+                           if value.is_nested
+                           else value[:, :0]
+                       )
        output = self.actor.train_mini_batch(data=data)
        return output
```

Here, `data` is shallow-copied first to avoid modifying the original data saved in TransferQueue. V1 only applies the
jagged TensorDict trimming in this section, and no longer applies the padded
DataProto trimming of `RayPPOTrainer.fit()` in the baseline document.

### Fully Async Component Changes

#### Preserving request_id of Partial Rollout

**File involved in the current version**: `verl/workers/rollout/llm_server.py`

**Corresponding file in the baseline document**:
`verl/experimental/fully_async_policy/fully_async_rollouter.py`. In the current version, the client has
migrated to the common `llm_server.py`, and this baseline file is no longer modified.

**Description**: Record the request IDs of the first segment and all inference segments in the partial rollout, used to associate the training-side data and track the complete inference process.

The current `FullyAsyncLLMServerClient` has migrated from `fully_async_rollouter.py` to the common `llm_server.py`. One partial rollout may be split into multiple actual vLLM requests due to abort and resume, so both the first segment request ID and all segment IDs need to be saved:

```diff
class FullyAsyncLLMServerClient(LLMServerClient):
    ...
    @rollout_trace_op
    async def generate(
        self,
        request_id,
        *,
        prompt_ids,
        sampling_params,
        ...
    ) -> TokenOutput:
        ...
        final_output = TokenOutput(
            token_ids=[],
            log_probs=[],
            num_preempted=0,
        )
        min_global_steps, max_global_steps = None, None
+       inference_request_ids = []

        while True:
            output = await super().generate(
                request_id=request_id,
                prompt_ids=prompt_ids + final_output.token_ids,
                sampling_params=sampling_params,
                ...
            )
+           inference_request_ids.append(output.extra_fields["request_id"])
            ...

        final_output.extra_fields["global_steps"] = global_steps
        final_output.extra_fields["min_global_steps"] = min_global_steps
        final_output.extra_fields["max_global_steps"] = max_global_steps
+       final_output.extra_fields["request_id"] = inference_request_ids[0]
+       final_output.extra_fields["inference_request_ids"] = inference_request_ids
        return final_output
```
