# OM与OM比对结果按模型图顺序展示

## 需求与范围

关联[排序需求 #535](https://gitcode.com/Ascend/msprobe/issues/535)。同网络不同版本的OM在多流场景中，dump时间戳顺序与模型图顺序可能不同。按内部Index展示结果不利于沿图查找首个精度异常算子。

新增`-mgf/--model_graph_file`，读取目标OM导出的图JSON，仅调整普通OM与OM同名比对的结果展示顺序。图JSON可通过`atc --mode=1 --om=<target.om> --json=<target.json>`获得。外层入口示例见[用户指南](../user_guide/accuracy_compare/offline_data_compare_instruct.md)。

`-mgf`与外层`-fr/-qfr/-cfr`（内层`-f/-q/-cf`）互斥，避免改变既有融合匹配语义。detail/mapping模式提示忽略图排序参数，并跳过该文件的校验和解析；参数互斥约束仍有效。

## 图序约定

展示顺序采用目标图JSON的数组位置，与既有融合规则解析器的全局ID排序分别处理。轻量解析器不调用融合匹配逻辑，也不读取节点`id`或`task_index_op_name`。

1. 按`graph`数组下标遍历各图，每个图内按`op`数组下标遍历节点。这里的op index指数组位置，不是节点`id`或CSV的原Index。
2. 名称按目标dump的模式规范化：`/`、`.`替换为`_`；普通模式复用`dump_parse.dump.handle_op_name(name, '')`处理`_lxsliceX`和`_sgt_graph_N`字段，FFTS模式与`DumpInfo`一致保留这些字段。目标dump名称已经经过该处理，不重复裁剪。名称必须是非空字符串，规范化后的空名或重名报错，避免把不同节点映射为同一个名称。
3. 节点`id`不参与展示排序，也不进行此字段的校验。缺失、重复或大小倒置的ID均不改变展示顺序。
4. 每个图的节点整体排列，再排列下一个图，禁止跨图穿插。跨图同名或规范化重名仍报错，因为当前dump名称不足以区分这些节点。
5. 为遍历到的图节点生成连续全局图序，构造`规范化名称 -> 图序`。没有dump的节点不会产生CSV结果行。

这是JSON中的图和节点展示顺序，不重建依赖拓扑，不按子图调用位置展开，也不推断多流运行时的实际时间顺序。主图的输出节点即使出现在子图之前，也保留其数组位置。

## 接入流程

```text
原有流程解析两侧dump并建立同名匹配
    -> 保留原FusionOp.op_id和任务分发顺序
    -> 根据目标侧算子名称构造原Index到展示序号的映射
    -> 原有流程计算并写出结果
    -> 使用展示映射稳定排序最终结果文件
    -> CSV第一列按结果行重编号为0～N-1，保持原有列结构
```

`CompareRule.make_index_to_graph_sequence()`在`parse_fusion_rule()`之后调用；启用图排序但匹配信息尚未初始化时，抛出带调用顺序提示的`CompareError`。未传`-mgf`时直接返回None。

最终排序键为：

- 未传`-mgf`：原Index。
- 已匹配图序：`(0, 展示序号, 原Index)`。
- 未匹配图序：`(1, 原Index, 原Index)`。

同一原Index的多条Tensor结果采用稳定排序，保留原相对顺序，但每条CSV结果行获得独立的新Index。新Index是展示行号，不是图节点ID、图内op index或内部FusionOp.op_id；全文件连续，多图之间不重新从0编号。

部分未匹配时告警并置后；全部未匹配时抛出参数错误，在计算和结果写出之前停止，提示检查`-mgf`是否属于目标OM以及dump与图的名称格式。未匹配项无法确定所属图，不插入任何已匹配图的结果中。非法JSON结构和无效名称明确报错。

排序入口明确区分三种状态：`None`表示沿用原Index排序且不重编号；空字典表示无有效图序，报错且不改写文件；非空字典交由独立的图序排序函数处理，CSV逐行重编号，文本保持原编号。正常比对路径在构造映射时已拦截全未匹配，输出入口的空字典检查用于防止直接调用时改写原编号。

CSV保持原有列结构，仅更新第一列Index，其他列的位置和数值保持不变。排序函数在比对完成后对含原Index的结果文件调用一次，原Index仅在内存中用于查询图序和排序。未传`-mgf`时不重编号；旧式文本结果不重编号。

Advisor在排序后读取CSV，输出的Index对应新展示行号，日志仍使用内部原编号。`--select/--range`的选择依据仍为既有OpSequence，不接受新CSV行号作为替代。

外层CLI仅增加`-mgf`参数透传，保留既有子进程失败处理：`call_msaccucmp()`将0和2视为成功，其他返回码记录错误日志；`compare_offline_data_mode()`不因子进程非零返回码新增异常或改变外层退出行为。脚本缺失、进程启动异常等既有异常处理仍保留。统一退出码和CLI异常展示另行评审。

## 验收与测试

- 解析器：图内ID倒置、跨图ID交叉或重复、ID缺失或包含无关值时均按graph/op数组位置排列；检查结构、普通/FFTS名称规则和特殊字段规范化后的同图/跨图冲突。
- 多图：主图和子图整体按数组位置排列，主图output不跨图移动；跨图重复名称明确报错。
- 映射与输出：内部op_id与匹配关系不变；CSV列结构不变，新Index严格为0～N-1；除Index外各列的完整行多重集合一致；同算子多Tensor行稳定；全未匹配时拦截比对，直接传空映射时CSV/TXT原文件字节不变。
- 入口：未传参数兼容，融合参数互斥，detail/mapping模式忽略图文件；带或不带`-mgf`时均保持原有子进程返回码处理和外层退出行为。
- 真实数据：用双OM的真实dump和未修改的目标图JSON验证输出；历史上板结果应注明对应提交，不能替代后续修改的验证。

纯解析和排序测试不依赖NPU。上板端到端验证、whl包验证及仓库完整CI是独立的验证步骤，应分别记录结果。
